# TT-269: 회원 탈퇴 및 차단 API 구현 계획

**작성일**: 2025-01-29  
**수정일**: 2025-01-29  
**목적**: User 도메인에 회원 탈퇴 및 차단 기능을 추가하고, 사용자 상태를 ACTIVE/INACTIVE/BLOCKED Enum으로 관리

## 현재 상태 분석

- User 엔티티에 이미 `status` 필드가 String 타입으로 존재
- UserProfile 엔티티에도 `status` 필드가 String 타입으로 존재
- UserCredential 엔티티에도 `status` 필드가 String 타입으로 존재
- 현재 status 필드들은 시스템 관리 상태를 위한 용도로 사용 중
- 회원 탈퇴 기능이 구현되지 않음

## 구현 계획

### 1. UserStatus Enum 생성
- 위치: `com.graydang.app.domain.user.model.enums.UserStatus`
- 값: 
  - ACTIVE (활성) - 정상적으로 서비스 이용 가능
  - INACTIVE (비활성/탈퇴) - 사용자가 직접 탈퇴
  - BLOCKED (차단) - 관리자에 의해 차단됨
- 추가 메서드: 
  - 상태 설명
  - 로그인 가능 여부 체크 (ACTIVE만 true)
  - 상태 변경 가능 여부 체크

### 2. 엔티티 수정
#### User 엔티티
- 기존 String status 필드를 UserStatus Enum으로 변경
- @Enumerated(EnumType.STRING) 어노테이션 추가
- 기본값: ACTIVE
- 탈퇴일시 필드 추가: `withdrawnAt` (LocalDateTime, nullable)
- 차단일시 필드 추가: `blockedAt` (LocalDateTime, nullable)

#### UserProfile 엔티티
- 기존 String status 필드를 UserStatus Enum으로 변경
- @Enumerated(EnumType.STRING) 어노테이션 추가
- 기본값: ACTIVE

#### UserCredential 엔티티
- 기존 String status 필드를 UserStatus Enum으로 변경
- @Enumerated(EnumType.STRING) 어노테이션 추가
- 기본값: ACTIVE
- OAuth 제공자별 계정을 개별적으로 비활성화할 수 있도록 관리

### 3. Service 계층 수정
#### UserService
- `withdrawUser(Long userId)` 메서드 추가
- 탈퇴 로직:
  - 현재 사용자 인증 정보 확인
  - User 상태를 INACTIVE로 변경
  - UserProfile 상태를 INACTIVE로 변경
  - 모든 UserCredential 상태를 INACTIVE로 변경
  - withdrawnAt에 현재 시간 저장
  - 관련 데이터 처리 (소프트 삭제)
  - 트랜잭션으로 원자성 보장

#### AdminService
- `blockUser(Long userId)` 메서드 추가
- `unblockUser(Long userId)` 메서드 추가
- 차단 로직:
  - 관리자 권한 확인
  - User 상태를 BLOCKED로 변경
  - UserProfile 상태를 BLOCKED로 변경
  - 모든 UserCredential 상태를 BLOCKED로 변경
  - blockedAt에 현재 시간 저장
- 차단 해제 로직:
  - 관리자 권한 확인
  - User 상태를 ACTIVE로 변경
  - UserProfile 상태를 ACTIVE로 변경
  - 모든 UserCredential 상태를 ACTIVE로 변경
  - blockedAt을 null로 설정

### 4. Controller 수정
#### UserController
- DELETE `/api/v1/users/me` 엔드포인트 추가
- 인증된 사용자만 본인 탈퇴 가능
- 성공 시 200 OK, 실패 시 적절한 에러 코드 반환

#### AdminController
- PUT `/api/v1/admin/users/{userId}/block` 엔드포인트 추가
- PUT `/api/v1/admin/users/{userId}/unblock` 엔드포인트 추가
- 관리자 권한 필요 (@PreAuthorize("hasRole('ADMIN')"))
- 성공 시 200 OK, 실패 시 적절한 에러 코드 반환

### 5. 보안 및 검증
- JWT 토큰 검증을 통한 본인 확인
- 이미 탈퇴한 사용자 재탈퇴 방지
- 이미 차단된 사용자 재차단 방지
- INACTIVE 또는 BLOCKED 상태 사용자 로그인 차단
- OAuth2 로그인 시 상태 확인 로직 추가

### 6. 영향 범위 고려사항
- 인증(Auth) 도메인: INACTIVE/BLOCKED 사용자 로그인 차단
- 댓글(Comment) 도메인: 탈퇴/차단 사용자의 댓글 처리 방식 결정
- 북마크/좋아요: 탈퇴/차단 시 처리 방식 결정
- 관리자 페이지: 사용자 상태 표시 및 차단/해제 기능

### 7. 테스트 계획
- UserStatus Enum 단위 테스트 (로그인 가능 여부 확인)
- UserService 탈퇴 로직 단위 테스트
- AdminService 차단/해제 로직 단위 테스트
- UserController 통합 테스트
- AdminController 통합 테스트
- 탈퇴/차단 후 로그인 차단 테스트

## 주의사항

1. **데이터 보존**: 법적 요구사항에 따라 일정 기간 데이터 보존 필요
2. **복구 정책**: 탈퇴 후 일정 기간 내 복구 가능 여부 결정
3. **CASCADE 처리**: 연관된 엔티티들의 처리 방식 신중히 결정
4. **트랜잭션 관리**: 탈퇴 처리는 반드시 트랜잭션 내에서 수행

## 구현 순서

1. UserStatus Enum 수정 (BLOCKED 추가)
2. User 엔티티에 blockedAt 필드 추가
3. OAuth2 서비스에서 BLOCKED 상태 확인 로직 추가
4. AdminService 차단/해제 로직 구현
5. AdminController 차단/해제 엔드포인트 추가
6. 인증 필터에서 INACTIVE/BLOCKED 사용자 차단 로직 추가
7. 테스트 코드 작성
8. API 문서화 (Swagger)

## 추가 고려사항

### UserProfile 상태 관리
- 회원 탈퇴 시 UserProfile의 status도 INACTIVE로 변경
- 사용자 차단 시 UserProfile의 status도 BLOCKED로 변경
- 프로필 정보는 보존하되 비활성화 상태로 관리
- 닉네임 중복 체크 시 INACTIVE/BLOCKED 사용자는 제외

### UserCredential 상태 관리
- 회원 탈퇴 시 모든 OAuth 연결 계정을 INACTIVE로 변경
- 사용자 차단 시 모든 OAuth 연결 계정을 BLOCKED로 변경
- 복구 시 사용자가 선택적으로 OAuth 계정 재활성화 가능
- 특정 OAuth 제공자만 연결 해제하는 기능도 고려

### 상태 전환 규칙
- ACTIVE → INACTIVE: 회원 탈퇴
- ACTIVE → BLOCKED: 관리자 차단
- BLOCKED → ACTIVE: 관리자 차단 해제
- INACTIVE → ACTIVE: 불가 (재가입 필요)
- BLOCKED → INACTIVE: 불가
- INACTIVE → BLOCKED: 불가
